## 6. 局限（读这张表前先看这五条）

1. **n=5，且同种子是确定性的**：方差来自"种子之间"，不是"同一设定的重复噪声"⇒ 本档给的是**经验分布**，不是置信区间；
   不做任何显著性/效应量陈述（统计数值结论属红线，交人工）。
2. **库存触顶 9999 造成截尾（censoring）**：`saturatedResources` 与 `badResource` 判定见 harness `:216-224`；
   wood/stone 在均衡策略 5/5 或 4/5 顶在上限 ⇒ 它们的"极差小"**不代表产能稳**，超额部分未被计入（0304 遗留"需加埋点"仍未解）。
3. **人口不是独立演化通道（在册方向性事实，必须带进任何人口/粮食分布的解读）**：
   `gameStore.ts:2619-2621` 每日把 `resources.people` 无条件归一为四阶层之和（`totalPopulation(populationClasses)` 不等则覆写），
   而 `gameStore.ts:2893-2899` 读档时的防软锁补足（`people < 已占用劳力 → 抬到已占用量）**会被次日这条归一抹平**。
   出处：`docs/insights/c927-16-population-dual-source-adjudication.md`（该档对"后者是否现役真回归"仍标待人工）。
   ⇒ 本档的人口分布是"经归一后的单通道读数"，**不得**按"people 独立演化"建模。
4. **harness 不是玩家**：策略是编译期写死的贪心/均衡两段启发式（`:92-208`），"国格 5/5 达 1／贪心 5/5 卡 1"是**策略形状的后果**，
   不是引擎可达性的上界。地图 80×80 全平原（`:31-32`）固定，不含地形差异 ⇒ 分布不含地理方差。
5. 未做：时间序列埋点（0304 遗留 2，属写码）、事件采样与经济的分离归因、跨模式（`getBalanceConfig` 的模式选表）对照。
