## 二、两案（＋一个登记变体）：存档语义影响

1. **案 A｜拒载**（`!Number.isInteger(rawCurrentDay)` → `throw SaveLoadError`）
   - 行为增量：**只**落在「`currentDay` 为非整数且 0 ≤ d ≤ 3600」的档上——整数档两案都放行（`guardA(42)=42`）。范围明确、不外溢。
   - 🔴 **兼容代价（本单最硬的一条，锚点未证）**：**本仓自己的当前版本会把小数写回磁盘**。探针 B：`deserialize(100.5)` → `serialize` → JSON 往返 → **`currentDay=100.5`、`schemaVersion=9`**（:325 写侧零净化）。⇒ 这类档**不是「外部脏档」而是「自家产品写出的合法档」**，A 一上线就把玩家手里已在玩的档**永久锁死**，且**没有补救通道**：`deserialize` 只在 `schemaVersion < SAVE_SCHEMA_VERSION` 时才走 `runMigrations`（:395），v9 档对 v9 码**不迁移**。
   - 收益：错误面明确（与 :455 既有 `out of range` 同型），不引入静默改值。
2. **案 B｜钳制**（`Math.floor(rawCurrentDay)`）
   - 兼容代价：**零**——`Math.floor` 对整数是恒等，⇒ 对**所有正常档逐位无影响**，只把已污染的档往前退 `<1` 天（探针 E：`100.5 → 100`，位移 −0.5）。
   - 语义代价：日历三元组**不变**（`calendar.ts:7` 自己就 floor，`dayToCalendar(100.5) === dayToCalendar(100)`），但**状态内的 day 本体变**⇒ `% 30`／`% 120` 门控（`gameStore.ts:2012`、`:2730`、`:1258`）**由「永不成立」变为可成立**＝**节奏／经济域行为改动**，属红线，**判定留人工，本单不代评**。
   - 收益：一次改动即同时收口 G1 与「小数永久存活」，玩家无损。
3. **案 C｜登记变体：拒载 ＋ 升 `SAVE_SCHEMA_VERSION` 9→10 ＋ 加 `migrations[9]` 做 floor**（A 的明确错误面＋B 的兼容性）
   - v9 及更旧档走一次迁移被洗干净，新写侧按整数校验；代价＝**升 schema 版本是一次跨面动作**（`runMigrations` 断链口径 :201-213、future-version 报错面 :388-390、引 `SAVE_SCHEMA_VERSION` 的测试与迁移档），且本仓 migration 域**另有在途未入库件**（`docs/insights/c927-21-migration-design-gap.md`、`c927-23-migrations-value-adjudication.md`、`c927-22-savehash-impl-design.md` 均未跟踪，**本单未引其内容、未碰**）⇒ 若走 C，应与那批单合并裁定，不由本单拆票。
