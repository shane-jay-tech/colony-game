## 4. 复算时必守的三条口径陷阱（继承 19 号头部，本单实测复核）

1. 🔴 **条目计数禁用大小写敏感字符类**：`grep -oE '^- [a-z0-9-]+\.md' \| wc -l` 比 `grep -c '^- '` **少 1**——本目录有 camelCase 名 `colony-unreachable-resourceSystem-20260912.md`（大写 `S` 不被匹配）。这就是在册 74/75 争议的根因（19 号头部 §结案）。本单复跑 111 vs 111 一致，未踩该坑。
2. **`sed 's/ —.*//'` 依赖每条条目行都含 ` — ` 分隔符**：19 号现 111/111 满足。⇒ 草稿若插入不含 ` — ` 的行，`comm` 会假漏列。本单草稿全部按 `<名>.md — <摘要>` 生成。
3. **末行换行／CRLF**：`wc -l` 与 python `splitlines()` 在末行无换行时差 1；本仓 insights 档多为 CRLF，`sed` 顺手吃掉尾部 `\r`，python 侧要显式 `rstrip('\r')`。本班全部读数用 python 复算并逐条与 shell 口径对齐。
4. 本机 `rg` 可用（ripgrep 15.0.0），但 19 号头部自述「rg 只在交互式 shell 是 alias」——本单实测 `rg --version` rc=0 ⇒ **该句在 HEAD 已过期**（c927-47 亦全程用 rg 直跑）。登记不改动原句（旧快照零改动）。
