## 一、建筑提前解锁修复（用户③，最具体的 bug）
**根因**：`isBuildingUnlocked` = `grade≥tier-1` 且 `upgradeRequires` 全满足。7 个进阶建筑 `upgradeRequires` 为空 → 只受国格门控，无需任何国策即在到达对应国格时出现：
练兵场/马厩/战车坊/禁军府/天文台/太庙/驿站。
**修复**：按主题加 `upgradeRequires` 国策门控（沿用 兵营→征兵、铜冶坊→采铜 既有范式）：
- 练兵场·马厩 → `pol_militia`（民兵）
- 战车坊 → `pol_chariot_corps`（车马军制，精确同名）
- 禁军府·太庙 → `pol_imperial`（王制，避开兵道互斥死锁）
- 天文台 → `pol_school`（兴学）
- 驿站 → `pol_post_road`（驿道）
**死锁核验（DeepSeek 复审确认无环）**：国策只依赖国策、不依赖建筑；被门控建筑产出的资源都不是其门控国策的成本。祭祖建筑(产礼器)**保持不门控**——否则与"祭祖国策需礼器"成环。
**门控后行为**：未采政策的进阶建筑在建造栏 `prereq_locked`（隐藏），采纳后出现 → 杜绝"提前解锁"。
新增回归守护测试（buildingsExpanded.test）。

## 二、国策树 HOI4 化（用户①）
**两位评审一致判定的根本问题**：
- 旧布局 x=深度、y=分支（横向带状），但连线代码按"子在父下方"画 → 出现"倒灌"扭曲折线（DeepSeek EDGE-01 BLOCKER：loom_workshop y=80 在其父 silkworm y=180 之上）。
- 无互斥可视化、无分支列标题、注释与数据不符（LOGIC-01）。
**重构**：
1. **24 节点坐标全重排**为 HOI4 式：branch=竖直列（农桑/工坊/礼制/保甲/外交/学问 自左向右），tier=水平行（y：T1=100/T2=230/T3=360），互斥/多根同行并排，**子节点一律在父下方** → EDGE-01 连线倒灌问题随布局消失。
2. **分支列标题**：每列顶部金色 branch 名（COORD-01）。
3. **互斥连接符**：互斥兄弟顶部红色横杠 + 中点 ×（DES-01）。
4. **可读默认缩放**：树很宽，原 fit-to-screen 会把字缩到看不清；改为 zoom=max(0.8,min(1.0,fitW))、横向溢出左对齐靠拖拽（HOI4 式）。
5. 订正 policies.ts 头部注释为真实的"双父分叉"结构（LOGIC-01）。
新增 policies.test 5 条布局不变量（前置存在/子在父下/tier 递进/互斥对称/无重叠）。

## 残留风险（≥2）
1. **门控收紧改变了节奏**：进阶军事/科技建筑现在必须先投相应国策——更有策略深度，但可能让某些打法觉得"前期能造的变少了"，需 playtest 校准是否过严。
2. **舟师 doctrine 锁死战车**：选 pol_naval_corps 后永不能造战车坊（设计意图的 doctrine 取舍），但若玩家不懂会困惑"为何造不了战车"——典册已解释互斥，仍建议 playtest 观察。
3. **国策树默认 0.8 缩放 + 需横向拖拽**：宽树不再一屏全见，非 HOI4 老玩家可能一时找不到右侧分支（已有"拖拽平移"提示 + 列标题辅助寻路）。

## 反方观点
最强反对：把国策树彻底 HOI4 化（宽树+拖拽）牺牲了"一屏俯瞰全局"的便利，对休闲/触屏玩家未必比原紧凑布局好——若 playtest 反馈"找不到分支"，可考虑加一个"缩小看全貌"快捷键或分支跳转标签作为补偿。

## 追加二（同日第三轮：军务 bug + 意识形态深度）
用户：①军务界面"按着才看得见，松开就消失" ②国策/朝令该加深度——主题是"封建帝国→三主义"(公/家/货)。

- **②a 军务秒关 bug（根因+系统修）**：MilitaryPanel(及大业/典册/民/设置) 点遮罩 pointerup→close；而 HUD 按钮在 **pointerdown** toggle 打开 → 打开那一下的"松手"落到刚弹出的全屏遮罩上→立即 close。修：把 HUD 面板类按钮（朝堂/邦交/军务/大业/?/民/设置）一律改为 **pointerup** 触发（速度键保持 pointerdown）。打开的松手此时命中的是按钮（遮罩尚未参与本次命中测试），面板正常开启并停留；之后点遮罩仍可关闭。
- **②b 意识形态深度（核心主题落地）**：发现 `pushStoryAxis(def.storyAxisDelta)` 对国策(gameStore:1098)/朝令(1121) **早已接线但全部 0 携带** → 采纳国策/朝令此前完全不推动"封建→三主义"漂移（仅靠事件）。修：
  - 新增**集中映射表** `POLICY_AXIS`/`DECREE_AXIS`（policies.ts/decrees.ts 末尾，加载时合并入各 def.storyAxisDelta），把 ~30 国策 + ~10 朝令按意识形态打 power(集权↔还权)/production(私有↔公有) 倾向。
  - 国策树/朝令 tooltip 新增"倾向：集权·公有"等行（axisLeanText），让取向**可见**。
  - 经 **Kimi 方案审**指出两漏洞并据此**重平衡**：㈠公有国策多半带集权→公天下(还权+公有)难凑齐 → 抬掉公益国策的集权拖拽（常平仓 -3/+8→0/+10、仓储 -4→-2、屯田 -3→-1、屯戍 -3→-2），并给还权国策补公有（稷下 +2→+4、百家 +3→+4、合纵 +0→+2、兴学/会盟 +1）；㈡货天下太被动 → 给商贸国策补轻还权（通市/铸币/通工 +1~+3 power），使货天下=**还权+私有**的主动路线。三路线现各有清晰支撑：家=集权(军事/王制/朝贡)、公=还权+公有(学问/民本/公益经济)、货=还权+私有(工坊商道)。
  - 新增 4 条 ideology 测试（含"公天下可无矛盾达成"：只用 power≥0 的国策即可双轴过 +34），964 全绿。

**协作**：本轮 Kimi 方案审（意识形态连贯性），据其两条漏洞重平衡；军务 bug 与轴接线为确定性修复 + 测试覆盖，未另起 DeepSeek 轮。
